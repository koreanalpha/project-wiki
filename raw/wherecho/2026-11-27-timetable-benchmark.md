# 어디초 #23 · 초1 하교 후 우리 집 일정

**승인 제안**　A안 ‘하루 타임라인’을 첫 일정 입력의 기본 흐름으로 승인하고, B안 ‘한 주 보드’는 요일 간 빈 시간 비교용으로 검토합니다. 두 시안 모두 같은 일정의 저장까지 6탭이었고, 저장한 일정이 첫 화면에 들어왔습니다. A안은 360px에서도 하교 → 빈 시간 → 저장한 일정의 순서가 읽히며, 빈 시간의 시작과 끝에서 바로 추가할 수 있습니다. B안은 다른 요일의 빈 시간까지 한눈에 보이지만 다섯 열에 긴 일정명과 시각까지 넣으면 밀도가 높아집니다.


## 동일 시나리오와 측정 환경

1. 빈 화면에서 `서울윤중초`를 검색하고 윤중초등학교를 고릅니다.
2. 월요일을 선택합니다. 운영은 학교 선택 직후 미리보기의 요일 선택기를 사용하고, 이어서 `17시쯤 → 아니요(돌봄) → 아니요(방과후) → 다 됐어요`를 거칩니다. 시안은 예시 하교 자료 및 17시 확인 범위를 사용합니다.
3. 월요일 14:00–15:00, 개인 일정 `도서관 읽기`를 입력하고 저장합니다. 운영은 `+ 일정 추가 → 직접 입력`, 시안은 월요일 빈 시간 버튼을 사용합니다. 해당 경로의 기본 시작·종료 시각을 그대로 사용했습니다.
4. 저장 직후 사용자 일정과 화면 피드백을 확인하고, 스크롤을 맨 위로 돌려 첫 화면 지표를 읽습니다. 각 조건에서 새로고침 후 입력한 일정이 다시 보이는 것도 확인했습니다.

2026-11-27 KST에 macOS Orca 내장 Chromium, DPR 1, 모바일 터치·CSS 뷰포트 360×800과 390×844에서 측정했습니다. 확장 키보드·브라우저 주소창·기기 안전 영역은 캡처에 포함되지 않습니다. 운영 [시간표](https://wherecho.co.kr/timetable)는 비로그인 상태에서 화면 크기마다 빈 localStorage를 확인한 새 Orca 격리 프로필로 재현했습니다. 초기 탐색에서 기본 프로필의 비어 있던 운영 origin에도 시험 초안이 생겼으며, 해당 시험에서 생성된 키를 제거한 뒤 측정에는 전용 격리 프로필만 사용했습니다. 시안은 로컬에서 제공한 정적 HTML이며 자체 로컬 저장 키를 사용합니다.

**저장의 의미**　운영 화면에서 새 개인 일정은 **후보**로 시간표 초안에 저장됩니다. `elementary-schedule-plans-v1`에 일정이 들어가고 새로고침 후 다시 보였습니다. ‘다 됐어요’ 때의 안내 완료 및 기본 정규수업 반영과 사용자가 직접 입력한 일정의 저장을 구분했습니다. 운영 계정, 공개 학교 데이터, 활동 요청·신청에는 변경을 가하지 않았습니다. 일반 운영 페이지를 열었으므로 통상적인 방문·사용 분석 이벤트는 발생할 수 있습니다. 시안에서 저장은 해당 브라우저의 예시 계획을 보존한다는 뜻이며, 실제 신청·알림·동기화 기능은 시안 범위 밖입니다.

- **유효 정보**는 첫 뷰포트의 과업 체크리스트를 화면에서 세었습니다. 빈 상태 3개는 학교 검색, 학교 없이 시작, 로컬 저장 안내입니다. 저장 후 8개는 학교명, 평일 전환, 선택된 요일, 해당 요일의 하교 시각, 해당 요일의 빈 시간, 저장한 일정 이름과 시간, 추가 버튼, 직접 입력 저장 피드백입니다. 시각·이름·버튼이 잘리지 않고 판독돼야 1개입니다. 운영에서 보이는 주간 합계는 ‘해당 요일의 빈 시간’에, 초안 완료 표시는 ‘직접 입력 저장 피드백’에 넣지 않았습니다. 둘 다 별도의 정보로 화면에 확인됩니다.
- **스크롤**은 동작 직후 열린 화면 구성에서 주요 세로 스크롤 영역의 `scrollHeight - clientHeight`를 CSS px로 실측했습니다. 운영은 내부 시간표 화면, 시안은 문서입니다. 저장 후 운영은 다른 요일 추가 카드가 열린 상태입니다. 시안은 에디터를 닫고 일정을 그대로 보여줍니다.
- **탭**은 브라우저에서 재현한 경로를 모바일 조작 수로 환산했습니다. 검색 필드 포커스와 제목 필드 포커스를 각각 1회, 네이티브 요일 선택기 열기와 월요일 선택을 2회로 셌습니다. 글자 입력, 스크롤, 새로고침은 제외했습니다. 운영 12회는 검색·결과 2 + 요일 2 + 안내 4 + 추가·직접 입력 2 + 제목·저장 2입니다. 시안 6회는 검색·결과 2 + 요일·빈 시간 2 + 제목·저장 2입니다. 물리 기기 탭 이벤트를 기록한 값은 아닙니다.
- **텍스트 전용 블록**은 첫 뷰포트 안에 완전히 들어오는 `main`의 `h1–h4`·`p` 중 내용이 있으며 버튼·링크·폼 필드를 품지 않는 요소를 1개씩 셌습니다. 버튼 레이블, 칩, 폼 레이블, 브랜드 및 하단 메뉴는 제외했습니다.

위 수치는 이 단일 시나리오와 번들에 대한 관찰값입니다. 텍스트가 긴 일정, 일정 여러 건, 실제 모바일 키보드가 열린 상태, VoiceOver·TalkBack, 운영 이식 후 화면은 측정 범위 밖입니다. 계정 기능이나 안내 질문을 포함한 실제 앱에서 같은 단축 폭이 유지되는지는 추정할 수 없습니다.

### 운영 화면 진단

- 첫 화면에 학교 검색과 학교 없이 시작이 함께 있어 두 진입 경로가 보입니다. 학교를 고르면 오후 미리보기와 한 주 질문이 이어지며, 보호자 귀가 시각이 빈 시간의 기준으로 남습니다.
- 월요일 일정 선택이 끝나도 `+ 일정 추가`가 화면 아래에 있습니다. 직접 입력은 유형·요일·시각을 명시하고 저장 후 다른 요일에 복사할 수 있습니다. 다만 이 경로에서 일정 선택 카드의 소개, 연결 버튼, 유형 칩이 입력 폼보다 앞서고, 저장 후 첫 화면을 다시 열면 학교 확인 카드가 일정보다 앞에 있습니다.
- 학교 확인과 후보 상태는 유지할 가치가 있습니다. 추천안은 일정과 빈 시간을 위에 배치하고, 학교 확인과 다른 요일 복사를 각 행동이 필요한 위치에서 열도록 제안합니다.

## 시안 검토

- **A · 하루 타임라인.** 상단에서 학교와 요일을 바꾸고, 선택한 날의 하교 시각·빈 구간·일정을 시간순으로 읽습니다. 빈 구간 또는 ‘+ 일정 추가’에서 하단 시트를 엽니다. 저장한 일정 전후에 12:50–14:00 70분, 15:00–17:00 120분을 각각 보여줍니다. 다른 요일을 비교하려면 해당 요일을 눌러야 합니다.
- **B · 한 주 보드.** 다섯 열의 하교 시각과 17시까지 남은 분을 비교합니다. 각 요일의 빈 시간을 눌러 가운데 편집 창을 열고, 선택한 요일의 상세에서 저장한 일정 이름과 시각을 읽습니다. 빈 시간의 총량이 보이므로 한 구간의 길이와 혼동하지 않도록 다음 검토에서 ‘빈 시간 합계’ 표시를 시험할 수 있습니다.
- **공통.** 학교 없이 시작, 예시 학교 검색, 요일·유형·시각 선택, 추가·편집·다른 요일에 복사·삭제, 입력 검증, 로컬 저장, 새로고침 복원을 제공합니다. 양식 레이블, 최소 44px 주요 컨트롤, 키보드 포커스 윤곽, 네이티브 모달·닫기, 저장 상태·오류 알림을 넣었습니다. 학교 검색과 하교 자료는 예시이며, 특히 월요일을 제외한 요일과 학교 미정 시간은 시연 값입니다. 학교 강좌 검색, 학원 연계, 학교 안내 확인, 운영 질문 카드·완료 판정과 운영 저장 구조 연동은 생략했습니다. 운영에서 기존 질문을 언제 꺼낼지는 TT-01의 하교 정보 대체 규칙과 세션 관찰 결과를 함께 보고 결정할 항목입니다.
